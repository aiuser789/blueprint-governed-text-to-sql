Governed Text-to-SQL

Ask in plain English, get one read-only SQL query that runs as the person asking. PostgreSQL filters the rows they may see and masks personal data to their tier before the model sees any value. Pick a person and a question below.

Asking as

Identity from the sign-in

The question never decides who is asking. Each question gets a short-lived token bound to one database connection, which the model's login cannot create.

Rows filtered by PostgreSQL

Row-level security scopes every row to the asker's region, book of customers or role, even for a query the model wrote badly.

Personal data masked in views

Names, emails, phones, addresses and IDs are masked per tier inside the database, so masked values are all the model ever sees.

Read-only, checked, audited

One read-only query, validated against an allowlist, run in a read-only transaction with a timeout. Every question is logged.

This page replays real runs of the blueprint against its synthetic data: a retail warehouse (5,000 customers, 50,000 orders) and a demo banking schema. Retail queries come from the blueprint's offline planner; banking queries were prepared for the demo. In both cases the validator, row-level security, masking and output scan are the real ones. With a model connected (Ollama, Anthropic or any OpenAI-compatible API) you can type any question. No real customer data is used anywhere.
