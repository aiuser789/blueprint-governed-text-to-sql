# Retail data

Everything in this blueprint is **synthetic**. No real customer, employee or order data is used anywhere.

- The warehouse itself is generated by `seed.py` in this folder (deterministic, seed `20260930`) when `sql-agent migrate` finds `core.customers` empty: 16 sales reps, 60 products, 5,000 customers, 50,000 orders from 2025-01-01 to 2026-09-30, about 125,000 order lines. Names are random pairings from short lists, emails use the reserved `example.com` domain, phone numbers sit in the fictional `555-01xx` block.
- `catalog.json` (this folder) — what the model is told about the analytics views, and what each PII tier sees per column.
- `glossary.json` (this folder) — the approved business definitions, the ambiguous terms the agent asks about, and the concepts the schema cannot answer.

The data is messy on purpose, because real warehouses are:

| Trap | What a naive query gets wrong |
|---|---|
| `orders.order_date` vs `orders.created_at` (keyed 0–4 days later) | month totals shift at the boundaries |
| `status = 'cancelled'` | revenue overstated by about 8% |
| 40 customers moved region on 2025-07-01 | `customers.region` ≠ `orders.region` for their older orders |
| Product names repeat across categories ("Classic Tee", "Travel Mug", "Desk Lamp") | grouping by name merges different products |
| Fiscal year starts 1 February | "this year" has two answers |
